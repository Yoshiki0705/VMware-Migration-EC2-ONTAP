# ブロック性能の実測を姉妹リポジトリから受け取るときの約束

このプロジェクトの検証項目「FSx for ONTAP iSCSI の IOPS / スループット実測」は、測定環境を
二重に作らず [S3-Burst-on-ONTAP-Files](https://github.com/Yoshiki0705/S3-Burst-on-ONTAP-Files)
の perf-matrix の結果を参照する方針にした。**このファイルは、その結果が来たときに何をしてよくて
何をしてはいけないかの記録である。** 数値が来る前に書いてあるのは、来てから思い出す形にすると
誤用するため。

## 引用してはいけない読み方

先方が挙げた 3 点と、先方が後から足した 4 点目。**4 つとも先方の実測または設計に基づく。**

**窓が 300 秒なのでベースラインとして引用しない。** 同じ環境で 1,536 MBps 構成の読みが 27 分かけて
2,882 → 1,439 MB/s へ落ちるのを先方が実測している。300 秒の値はバーストを含む。

**raw device の値なので、ファイルシステムを載せた場合の値ではない。** このプロジェクトの用途は
移行後のデータ領域（LUN の上にファイルシステムを作って `fstab` でマウント）なので、
**そのままでは「移行後のボリュームが出す値」として引用できない。** 「同一条件での上限の目安」
としてのみ引用する。

**NFS / SMB と同じ表に置かない。** 理由は 2 つあり、どちらも先方の実測。データ LIF が別ノードの
別ポートに載っていること、raw device にファイルシステム層が無いこと。

**スループット容量が違えば上限そのものが違う。** 先方の構成は 6,144 MBps・SSD 4,096 GiB・
プロビジョンド 200,000 IOPS。**引用時に先方の構成値を併記する。** こちらの移行先が別の容量なら
「同一条件」が成立しない。

## 数値を引用するときに必要な手続き

**先方の repo は申告制の probe で言い換え事故を防いでいる**（`make outgoing-probes` /
`incoming-probes`）。数値や主張を**転記**する場合は、引用する文を 1 行渡して先方の
`docs/agent/cross-repo-probe-contract.txt` に登録してもらう。

**単なるリンクには probe を登録しない。** 先方の contract の但し書きに「主張を転記していない
see-also のリンクに probe を登録すると、依存していない文言を凍結させることになる」とある。
現在このプロジェクトが持っているのはリンクだけなので、登録は無い。

登録が必要になるのは、たとえば「除数 625 MBps に対してブロックの実測は N%」をこちらの本文に
書いた時点。**そのときに登録を忘れると、先方が言い換えた瞬間にこちらの根拠が黙って消える。**
